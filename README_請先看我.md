# 投資記錄 — 第一層（盤後資料，不用開電腦）

這一包做的事：**GitHub 每個交易日盤後自動去證交所抓收盤資料，你的 app 直接讀，所以你在外面用手機打開就有最新數字，完全不需要開電腦、不需要任何金鑰。**

```
GitHub Actions（每交易日 14:40 自動跑）
   └─ scripts/fetch_twse.py  抓證交所／櫃買公開資料
        └─ 產出 data/*.json  自動 commit 回 repo
             └─ index.html   你的 app（GitHub Pages）讀這些 JSON
                  └─ 持股股數與成本 → 從你資產管理 app 的 Firebase 同步
```

**為什麼持股不放在 GitHub？** 因為 repo 要設成 public（免費版 Pages 的條件），
所以裡面只放「證交所本來就公開的股價」。你的持股張數與成本走 Firebase／瀏覽器本機，
不會出現在 repo 裡。

---

## 檔案

| 檔案 | 說明 |
|---|---|
| `index.html` | app 本體，單一檔案，可直接雙擊打開先看畫面 |
| `watchlist.txt` | 自選股清單（已填入你目前 7 檔持股） |
| `scripts/fetch_twse.py` | 抓資料並整理成 JSON |
| `.github/workflows/daily.yml` | 每交易日 14:40 自動跑 |
| `.github/workflows/backfill.yml` | 手動執行一次，回補歷史收盤（走勢圖要用） |
| `tests/*.json` | 假資料樣本，給 `--offline` 測試解析邏輯用 |
| `data/` | Actions 產生的資料，第一次跑完才會出現 |

## 你要做的事（一次性設定，約 15 分鐘）

### 1. 建一個新的 GitHub repo

名字隨意，例如 `my-invest`。**要選 Public**（免費版 GitHub Pages 只支援 public）。
裡面只有公開股價資料，沒有你的持股，所以 public 是安全的。

### 2. 把這個資料夾的檔案上傳上去

保持資料夾結構（`scripts/`、`.github/workflows/` 都要在）。
用網頁上傳的話，`.github` 這種開頭是點的資料夾要用「Add file → Create new file」，
在檔名欄直接打 `.github/workflows/daily.yml` 就會自動建資料夾。

### 3. ⚠️ 打開 Actions 的寫入權限（最容易漏掉的一步）

`Settings → Actions → General → Workflow permissions`
→ 選 **Read and write permissions** → Save。

沒開這個，程式抓得到資料但 commit 不回去，等於白跑。

### 4. 開啟 GitHub Pages

`Settings → Pages → Source` 選 **Deploy from a branch**，
Branch 選 `main` / `/ (root)` → Save。

過一兩分鐘你的網址就會出現，長這樣：
`https://你的帳號.github.io/my-invest/`

### 5. 手動跑第一次

`Actions` 頁籤 → 左邊選「每日盤後抓台股資料」→ 右邊 **Run workflow**。
跑完（約 1 分鐘）repo 裡就會多出 `data/` 資料夾。

### 6. 回補歷史（走勢圖才有東西看）

`Actions` → 選「回補歷史收盤（手動執行）」→ Run workflow → 月數填 `12`。
這個會跑 5～10 分鐘（它刻意放慢速度，避免被證交所當成攻擊），跑一次就好，之後每天自動累積。

### 7. 打開你的網址，填同步代碼

進到 app 的「設定」→ 填入你在**資產管理 app 設定頁用的那組同步代碼** → 儲存。
持股股數與成本就會自動同步過來，市值、報酬率會自己算。

> 不想用 Firebase 也可以：在「手動輸入持股」貼上 `代號,股數,平均成本`，一行一檔。

### 8.（可選）加到手機主畫面

用手機 Chrome / Safari 開你的網址 → 分享 → 加到主畫面。之後就像一個 app 圖示。

## 之後它會自己做的事

- 每個交易日 14:40（台灣時間）自動抓當日收盤，更新 `data/`
- 沒開盤的日子抓到的會是前一個交易日，程式會判斷、不會亂寫
- 走勢歷史每天累積一筆，最多留 1300 個交易日（約 5 年）

你完全不用管。人在外面、電腦關機，打開網址都是最新的收盤資料。

## app 有什麼

| 頁 | 內容 |
|---|---|
| **總覽** | 總市值、當日損益、總報酬與報酬率；持股佔比前四大 |
| **持股** | 全部持股，點一列展開：股數、成本、損益、殖利率、本益比／淨值比、收盤走勢圖（1月／3月／半年／全部） |
| **選股** | 漲幅、跌幅、成交量、殖利率排行；以及自訂篩選（殖利率、淨值比、本益比、股價） |
| **設定** | 同步代碼、手動持股、資料狀態、重新載入 |

右上角永遠顯示資料是哪一天的收盤；超過 3 天沒更新會變成黃色警示，
所以你不會誤把舊價格當成今天的。

## 想改東西的話

- **加減自選股** → 改 `watchlist.txt`，commit 後隔天生效（想立刻生效就手動 Run workflow）
- **改抓取時間** → `daily.yml` 裡的 `cron: "40 6 * * 1-5"`（UTC，台灣時間要減 8 小時）
- **改顏色** → `index.html` 最上面的 `:root` 那一段，全部顏色都集中在那裡
- **本機測試抓取邏輯**（不連網） → `python scripts/fetch_twse.py --offline tests`

## 常見問題

**Actions 跑完是綠燈，但 repo 裡沒有 data/**
→ 第 3 步的寫入權限沒開。開了之後重跑一次。

**網頁一直顯示「示範資料」**
→ 表示讀不到 `data/latest.json`。可能是還沒跑過 Actions，或 Pages 還在部署（等 2 分鐘重新整理）。
直接雙擊本機檔案打開時也一定會是示範資料，這是正常的（瀏覽器不允許本機檔案讀取其他檔案）。

**持股沒同步過來**
→ 同步代碼要跟資產管理 app 裡的那組**完全一樣**（大小寫也算）。
或者你的 Firebase 規則不允許讀 `assetMgmt` — 用手動輸入持股也可以。

**上櫃資料顯示失敗**
→ 櫃買中心有時會擋掉程式化請求。你的 7 檔持股全是上市，不影響；
只有「選股」頁的上櫃股票會少。

**排程好像沒跑**
→ GitHub 對「連續 60 天沒有任何 commit 的 repo」會自動停用排程，
會寄信通知你，進去按一下 Enable 就好。另外 GitHub 的排程本身可能延遲 5～20 分鐘，是正常的。
